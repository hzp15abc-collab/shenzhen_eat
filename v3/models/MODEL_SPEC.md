# V3 财务模型：从投入到关店清算
更新 2026-11-27（人民币元）。**这是条件情景模型，不是新和店铺真实经营流水、未来预测或贷款建议。** 采用两位合伙人共同经营，工资为0元；合伙人劳动投入及可能分配单独展示，新增受雇人员计真实雇主成本。V2保留但不参与V3运算。

## 1. 资料、研究方法与已将证据写入参数
四个结构化输入均读取并保留 SHA256：`../evidence/market_assumptions.json`（当地公开挂牌与潜在客单/需求测试）、`startup_costs.json`（装修、设备单价数量、库存开办项、每月支出）、`labor_capacity.json`（招聘样本、雇主预算、工作流程和产能）、`delivery_params.json`（官方收费口径、平台费用情景）。详见同名研究文件及原始链接。实际租约/商家合同/人流/销量/订单时间/经营许可均待核。投资假设不是当地平均值，售价、需求、人工产能、费用等多为明示的规划假设；研究源和检测记录与模型同行。 
方法参考：美国 SBA 官方盈亏平衡计算器 https://bec.www.sba.gov/breakevenpointcalculator （固定费用÷单位售价减变动费用）；英国 Insolvency Service 现金流指南 https://www.gov.uk/guidance/director-information-hub-cashflow （开业预备现金、支出和回款时间）。两项仅为通用计算方法，不套用外国税率/市场数据。中文成本法规及用工证据见对应研究。

## 2. 情景矩阵
5种模式（A传统早餐、B便携特色、C早餐＋零食、D多时段餐饮、E分时合作）×3个不同投入档（低/标准/高）×3种销售渠道组合（全线下、线下＋外卖、外卖较多）×3个市场情景（悲观/基准/乐观）＝135种配置，逐月36个月＝4860行。退出第3、6、12、24月＝540行。另135组单订单（5×3投入档×3市场×3渠道）完整分解。
- 投入档代表面积/设备/租金/转让费/押金和对应空间经济上限；低档假定存在可合法复用基础设施的场地和可直接租赁铺位，高档不是自动代表订单更多。暂用0.8/1/1.18的商街机会系数为测试（非观测），反映选址和面积差异，现场应替换。
- 悲观/基准/乐观订单和客单价取市场输入的低/基准/高情景值，不再乘另一组需求系数。再加开业爬坡、季节、竞争、新旧顾客结构、采购价和工资压力等明示假设。三情景非概率分布。未来竞争发生月份及分流均假设。
- 三渠道组合切分一个总订单需求池，全线下100%现场；混合75%现场/25%外卖；外卖较多40%现场/60%外卖。两平台在外卖需求中各50%，非平台市场份额；不把线上和线下重复累加，也不自动假定开外卖增加总需求。现场有数据才校准增量需求或客群替代。平台开通须实际合法、合同成立，E共享模式尤其不能默认可借用原店主体许可。
- 36月持续经营的所有结果都是反事实假设。如果中途无钱，记录必要追加资本才能算下个月，并不表示建议继续投入。退出情景独立清算，资金不足可止损。

## 3. 起步资金（第0月）
`初始投入实际支付/占用 = 装修 + 设备 + 转让费 + 开业杂费 + 外卖开通准备 + 房租押金 + 平台保证金 + 开业库存`。
`开业资金合计 = 初始投入实际支付/占用 + 现金储备`。
储备=前三个月的首月固定支出规模估计，**留在账户并未花掉**，只是情景缓冲，不保证足够。押金和库存属于资金占用，不是营业成本，可能按合同回收。装修设备逐项BOM见采购输入。转让报价可能包括设备、装修、预交租金或押金；无资产明细则不敢自作主张扣除，计算情景假设报价仅为未含重置资产的净进场费。实际若报价包含可用设备/装修/押金，必须以清单确认，模型可用 transfer_bundle_credit 录入已核实的重叠额，或者扣对应装修/设备/押金重置项，不能重复扣或计。故含全额转让再新置资产是条件预算，不是挂牌本身的实付金额。
供货及外卖设备准备仅计一次，日常平台推广放每月支出，商家承担优惠进入每单。房租从经营月开始（押金与预缴时间须按真实合同再校准）。
外卖全线下配置不含平台月推广、入驻准备及保证金。

## 4. 每天可实现多少订单？先问顾客，再看厨房和人
市场研究输入参考的聚合成人/家庭商业机会数×综合购买转化假设，按新客和老客两个互斥机会池分开；成熟老客机会比35%，开业期从8%起逐渐扩大。成熟基准转化率=成熟订单/机会。新客转化=成熟转化0.75倍，老客转化=(1−.65×.75)/.35倍，因此合计成熟转化等于输入。再乘开业爬坡、季节、竞争与档位因子，避免额外把复购当新增全部订单。真实成交率、人口、学生规模和平台订单不同，不能互相替代。
将潜在订单按渠道切分。线下与线上每份所需的人分钟不同，外卖增添包装、交接、核单；以两位亲自参与合伙人的每日有效服务人分钟（已扣采购/清洁/休息）＋雇员有效人分钟为共享人力上限。高峰总人分钟和设备每日能力另限。 
`实际订单分配比例 = min(1,全天有效人分钟÷所需人分钟, 高峰有效人分钟÷高峰所需人分钟, 设备量÷总需求)`；同一比例分配给各渠道。记录因瓶颈损失的订单，不假设无限出餐。全天与高峰是聚合假设，不是儿童出入日程。两位合伙人在较大 D 模式假设每人10小时/开门日（26日约260小时/月），强度较高且假设拥有必要烹饪和运营技能，实地需演练和合理替班。
雇员数每季复核，从合法空间和设备容许的0～max_staff里选使预计三个月经营结余最高者，计新人培训/调整支出假设。固定工资计入三个月内即使淡季订单不足也支付，不按单临时消失。雇主预算取低5800、标准7200、高8800元/月（毛薪、雇主负担及必要补贴；源招聘见用工研究；实际五险一金/加班/合同再确认）。对于D若合伙人不具备热厨专业技能，应额外估专技聘用10,800–12,500元/月的总雇主费用，不可只按普通店员套用。追加人手不增加无限设备能力；模型选择不聘用时，不代表实际可以无员工覆盖全部复杂工序。
有些线上订单毛利很低或为负：该数字是承担所选渠道配置的压力测试，不是盈利建议。

## 5. 一个订单的账
线下：顾客价－食材实际消耗（含普通损耗）－线下包装－支付费预算－共享场地分成（E）－税费风险预算。
外卖：货品标价（含商家实收包装费如有，不含消费者自行承担配送费）－商家承担优惠－退款期望损失＝货品净收入。
再扣平台技术服务/交易费（模型保守按优惠后货品金额、未假定退单返还）、商家实际承担骑手/物流成本（不扣消费者自己承担配送费）、食材实际消耗（普通损耗含在外卖研究基础成本里，避免重复）、外卖包装（替代堂食包装）、共享方分成、税费风险预算。分别输出美团和淘宝闪购。平台运费、促销和退款合同口径未取到，全部情景假设；2024美团公开披露6–8%技术费只是全国历史参照，不能当本地实际结算率；闪购费率未验证，全部为测试。同一基准两平台数字故意一致，因为未取得合同可以判断优劣。
单位食材成本以基础商品价格及成本比折算，随采购成本增幅而变动；不因售价下降自动让采购额同比降低。报损按正常率和场景倍率。每单税费风险预算暂按净收入1.5%，非现行法定税率或认定纳税义务，主体确定后需专业估税。 
`统一订单贡献 = 净收入 − 食材含损耗 − 包装 − 平台与配送 − 支付费 − 共享分成 − 订单税费预算`。尚需支付月固定支出。毛利只扣食材含损耗；净利润未扣折旧与现金流不可混用。

## 6. 每月经营结余、现金、分配、回本
月每类完成单数=每日实现×实际经营天数（26/30×当月自然天数）；按月经营销售额=每类订单×对应货品净收入。
固定成本=租金、管理、水电基础、其它运营、线下推广、平台月推广、实际已聘员工总雇主费用＋两位合伙人工资0元。每次招聘/人员调整预算另外列。 
`经营结余（现金经营利润）= 全部订单贡献−固定支出−人员调整费`；`近似会计利润=经营结余−装修、设备及转让摊销`（36/60/36个月假设，不是法定财税口径）。
`营运现金流=经营结余−存货资金变动−未结算平台应收款变动−设备维护资本支出`。存货目标按食材/包装的预计数日耗用量（开业库存已投入，变化项避免重复付货）；外卖平台回款滞后按净结算额对应若干天估算，不能把应收款当今天到账。维保预算0.8%货品净收入。
`期末账户余额=期初账户+营运现金流+投入补充款−分配款`。如果低于0，记录本月必要追加款和首次缺口，继续模拟只为压力测试。假设季度末在有超储备且没有累计补款前提下，可取超三个月固定支出储备的50%进行分配；数值按两位合伙人50/50仅演示（非既定合同）。超储备可分配只是模型假设，实际需核实未结税费/租约/合同、营运资金及新订单现金需用，不是承诺提款；各自实际劳动时间另列。 
日保本=正常月固定支出÷当前混合每单贡献÷当月开门天数。每单贡献须正；不包括变化存货和折旧，另有扣维修预算的现金保本量。保本日单量是静态门槛，不保证年盈利，不是已测客流。
回本月=累计营运现金流首次覆盖第0月实际支付/占用，不包括仍在账户的初始备用金；另外报告覆盖初始总资金（含备用金与累计补款）月份。**都不是当月已经把钱全部发给合伙人。** 已分配真实现金情景及剩余账户分开显示。

## 7. 退出清算：每个配置4个时间点
结业当天先算押金回收、设备折价、存货变现、平台保证金和应收款；装修转让回收按0保守估计。回收率悲/基/乐分别：房租押金45/75/95%，设备初始43/58/70%逐月减1.2/1/0.9个百分点（最低10%），库存30/50/70%，平台押金60/85/100%，平台应收回款85/95/99%。没有真实二手成交和合同保证，这些都是估值情景。费用另列提前退租1–3月（乐观.5月），雇员结清0.5–1.5月已聘人员雇主费用、清场与未结杂费，不是法定最低或最大法律赔偿，实际以合同和用工结算为准。
`回收净额 = 资产回收总额−退出支出`。
`退出当天净需追加款 = max(0,退出支出−留存现金−资产回收)`。若资产回收要等，**先付后收垫资**=max(0,退出支出−留存现金)；垫资临时金额不直接算终局损失，回收以后结清。
`退出返回合伙人的现金 = max(0,留存余额+资产回收−退出支出)`。
`两位投资者累计净损失 = 初始总资金+累计追加投入+退出净需追加−累计已分配−退出返回现金`。
其中负值为净赚；每位按50%仅示例。独立恒等式：`初始实际支付/占用 − 累计经营现金流 − 结业资产净回收`。二者一致，故不会把投入、实际累计经营亏损、追加资金重复计损，也没有把可回收库存、押金、备用金重复算收益。结业真实法律风险及设备能否变现未验证，模拟净损失不是最大可能损失上限。 
## 8. 数据文件 / 复算
- `model_v3.py`  Python3 标准库可运行：`python3 model_v3.py`。执行读取四份同级研究输入；先复制修改原始情景参数后重新运行，导出更新结果。不会改V1/V2。
- `model_inputs_v3.json`  实际解析使用的全量参数，四个证据输入 SHA256 和版本状态；`summary_v3.csv` 全135配置汇总，每个初始成本及三年关键金额。
- `monthly_v3.csv` 全4860逐月结余与现金，每渠道逐项单笔及合计、需求/实际容量/人工、保本、现金及分配。
- `exit_v3.csv` 540个退出逐项回收、费用、退出当天需追加、先付后收、最终损失双方分配。
- `unit_economics_v3.csv` 135个单位订单分解；`report_data_v3.json` 供排版：全汇总，基准标准混合5案例每月明细，全量轻量月度数据、全部退出和每单经济。
- `sensitivity_v3.csv` 单因素测试（见报告与模型代码）。
- `VALIDATION.txt` 自动核验：收入＝标价减折扣与退款、贡献＝收入减全部单变动成本、订单和共同人设备容量约束、工资0、现金恒等式、退出两种独立写法相同、案例数完整；独立复核见审计文件。
正文数字可四舍五入，附表保留精确期望值（订单模拟允许小数，实际须以整数交易记录重新标定）。多情景模拟不能替代营业、装修、租约和外卖的真实报价；用户拿到实际数值后替换相关参数。

## 9. 单因素复核与 D 专技招聘
`sensitivity_v3.csv` 54项单一因素重算，需求±20%、线下价-10%、食材+10%、租金+20%、实际雇员费+10%、每单骑手+2元、平台费+3个百分点、商家优惠+5个百分点、额外线上增长20%（仅独立假设，基准没有）、已核实转让费内2万元可以替代重复项目（只测试重叠影响、不声称实际能省）。除单项外保留基准，其灵活聘用动态重算，非简单乘差额。
另 `skilled_cook_sensitivity_v3.csv/json`：D若两位合伙人没有实际承担热厨的专业能力，专技厨师成为刚性必要人员。按用工研究11,600元/月完整雇主成本测试第一名员工（不是在普通工资之上再整笔叠加），更多员工仍用相应普通用工预算；另算低/标准/高档和基准/乐观情景。常规模型的D结果明确基于合伙人具备技能；此专技测试不修改135种基准输出。运行 `python skilled_cook_v3.py` 可复算。
`validate_v3.py` 作为与生成逻辑独立的CSV读取检查，逐行重新求和及核算现金、退出、源输入SHA256。 `CSV_VALIDATION.txt` 保存最终执行结果。
